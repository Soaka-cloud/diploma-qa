# API-тест-кейсы (Yougile REST API v2)

Базовый URL: https://yougile.com/api-v2
Авторизация: заголовок `Authorization: Bearer <token>`; токен получается в сценарии S-API-01 и сохраняется в переменную коллекции `token`.

Каждый сценарий соответствует подпапке Postman-коллекции `yougile_diploma.postman_collection.json`: имя подпапки = имя сценария, внутри подпапки — все запросы сценария по шагам (включая предусловия, например создание проекта перед редактированием).

## S-API-01. Авторизация: получение ключа доступа

- Тип: позитивный
- Предусловия: известны логин и пароль учётной записи Yougile
- Шаги:
  1. POST /auth/keys/get, тело `{"login": "…", "password": "…"}` — ожидаем статус 200
- Ожидаемый результат: в ответе массив ключей доступа; первый ключ сохранён в переменную `token`

## S-API-02. Создание проекта

- Тип: позитивный
- Предусловия: получен ключ доступа (S-API-01)
- Шаги:
  1. POST /projects, заголовок Authorization, тело `{"title": "Дипломный проект"}` — ожидаем статус 201
- Ожидаемый результат: создан проект, в ответе поле `id`; id сохранён в переменную `projectId`

## S-API-03. Получение проекта по ID

- Тип: позитивный
- Предусловия: получен ключ доступа
- Шаги:
  1. POST /projects — создать проект (предусловие сценария) — ожидаем 201; `id` → `projectId`
  2. GET /projects/{projectId} — ожидаем статус 200
- Ожидаемый результат: в ответе объект проекта с `id`, совпадающим с запрошенным

## S-API-04. Редактирование проекта

- Тип: позитивный
- Предусловия: получен ключ доступа
- Шаги:
  1. POST /projects — создать проект (предусловие сценария) — ожидаем 201; `id` → `projectId`
  2. PUT /projects/{projectId}, тело `{"title": "Дипломный проект (изменён)"}` — ожидаем статус 200
  3. GET /projects/{projectId} — проверить, что название изменилось — ожидаем 200
- Ожидаемый результат: название проекта обновлено и подтверждается при получении по ID

## S-API-05. Удаление проекта

- Тип: позитивный
- Предусловия: получен ключ доступа
- Шаги:
  1. POST /projects — создать проект (предусловие сценария) — ожидаем 201; `id` → `projectId`
  2. PUT /projects/{projectId}, тело `{"deleted": true}` — ожидаем статус 200
- Ожидаемый результат: проект помечен как удалённый (мягкое удаление); в ответе `id` совпадает

## S-API-06. Создание задачи

- Тип: позитивный
- Предусловия: получен ключ доступа
- Шаги:
  1. POST /projects — создать проект (предусловие сценария) — ожидаем 201; `id` → `projectId`
  2. GET /boards — получить доску проекта — ожидаем 200; `boardId`
  3. GET /columns?boardId={boardId} — получить колонку доски — ожидаем 200; `columnId`
  4. POST /tasks, тело `{"title": "Дипломная задача", "columnId": "{columnId}"}` — ожидаем статус 201
- Ожидаемый результат: задача создана в колонке доски проекта, в ответе поле `id`

## S-API-07. Редактирование задачи

- Тип: позитивный
- Предусловия: получен ключ доступа
- Шаги:
  1. POST /projects — создать проект (предусловие сценария) — ожидаем 201
  2. GET /boards — получить доску проекта — ожидаем 200; `boardId`
  3. GET /columns?boardId={boardId} — получить колонку — ожидаем 200; `columnId`
  4. POST /tasks — создать задачу (предусловие сценария) — ожидаем 201; `id` → `taskId`
  5. PUT /tasks/{taskId}, тело `{"title": "Дипломная задача (изменена)"}` — ожидаем статус 200
  6. GET /tasks/{taskId} — проверить, что название изменилось — ожидаем 200
- Ожидаемый результат: название задачи обновлено и подтверждается при получении по ID

## S-API-08. Негативные сценарии

- Тип: негативный
- Предусловия: получен ключ доступа (кроме шага 1)
- Шаги:
  1. GET /projects без заголовка Authorization — ожидаем статус 401
  2. POST /projects с пустым телом `{}` — ожидаем статус 400 (сообщение валидации про пустое название)
  3. GET /projects/{00000000-0000-0000-0000-000000000000} — ожидаем статус 404
  4. POST /auth/keys/get без пароля — ожидаем статус 400
- Ожидаемый результат: API корректно возвращает ошибки: 401 без токена, 400 при невалидных данных, 404 для несуществующего ресурса

Итого: 8 сценариев (7 позитивных, 1 негативный — 4 негативные проверки).
