## Описание проекта

Проект направлен на тестирование системы управления проектами Yougile — веб-приложения для организации командной работы: создание проектов, постановка задач, отслеживание статусов на канбан-досках, ведение комментариев.

Приложение выбрано, потому что: открытая документация API, бесплатный доступ, стабильный веб-интерфейс без анти-бот-защиты — подходит для полного цикла тестирования (UI + API) без риска блокировки.

## Объект тестирования

Выбраны три ключевые функции:

1. Авторизация — вход в аккаунт и выход из него.
2. Управление проектами — создание, просмотр, редактирование и удаление проектов.
3. Управление задачами — создание задачи на доске, изменение названия, перенос по колонкам (изменение статуса), добавление комментария.

## Подход к тестированию

- Функциональное тестирование — позитивные сценарии использования ключевых функций.
- API-тестирование — позитивные и негативные сценарии: пустые поля, невалидный токен, неверные данные, неподдерживаемый метод.
- UI/UX-тестирование — корректность отображения элементов, понятность навигации, обработка ошибок ввода.
- Кросс-браузерное тестирование — проверка ключевых сценариев в Microsoft Edge, Google Chrome, Mozilla Firefox.
- Тестирование доступности (базовое) — навигация с клавиатуры, читаемые подписи и атрибуты элементов.
- Регрессионное тестирование — повторный прогон автотестов после исправлений.
- Нагрузочное тестирование не проводится на боевом сайте (риск блокировки IP или учетной записи).

## Сценарии тестирования

### Функциональные сценарии (UI)

Полные тест-кейсы (шаги, предусловия, ожидаемые результаты) — в приложении «Функциональные тест-кейсы» (файл test-cases-functional.xlsx).

| ID | Сценарий |
|---|---|
| TC-01 | Вход в систему с корректными данными |
| TC-02 | Создание проекта |
| TC-03 | Редактирование названия проекта |
| TC-04 | Создание задачи на доске |
| TC-05 | Изменение статуса задачи (перенос по колонкам) |

### API-сценарии

Детальные шаги (методы, URL, тела запросов, ожидаемые статус-коды) — в приложении «API-тест-кейсы» (файл test-cases-api.xlsx) и в Postman-коллекции yougile_diploma.postman_collection.json. В коллекции каждый сценарий — отдельная подпапка (имя подпапки = имя сценария), внутри подпапки — все запросы сценария по шагам.

| ID | Сценарий | Последовательность запросов |
|---|---|---|
| S-API-01 | Авторизация: получение ключа доступа | POST /auth/keys/get |
| S-API-02 | Создание проекта | POST /projects |
| S-API-03 | Получение проекта по ID | POST /projects → GET /projects/{id} |
| S-API-04 | Редактирование проекта | POST /projects → PUT /projects/{id} → GET /projects/{id} |
| S-API-05 | Удаление проекта | POST /projects → PUT /projects/{id} (deleted: true) |
| S-API-06 | Создание задачи | POST /projects → GET /boards → GET /columns → POST /tasks |
| S-API-07 | Редактирование задачи | POST /projects → GET /boards → GET /columns → POST /tasks → PUT /tasks/{id} → GET /tasks/{id} |
| S-API-08 | Негативные сценарии | без токена (401); пустое тело (400); несуществующий id (404); авторизация без пароля (400) |

Доступность API подтверждена на старте проекта: GET /api-v2/projects без токена возвращает 401, POST /api-v2/auth/keys с пустым телом возвращает 400 с сообщениями валидации — API отвечает корректно и пригодно для тестирования.

## Используемые программные средства

- TestIT — управление тестированием (тест-кейсы, чек-листы)
- Ёжка — баг-трекинговая система
- Postman — коллекция API-запросов, выполнение позитивных и негативных тестов, автоматизация через тест-скрипты
- Yonote — система для документации
- GitHub — публичный репозиторий проекта автоматизации
- Allure — формирование отчетов о прогонах автотестов
- Python 3.11, pytest, Selenium, Requests — стек автоматизации
